# Aris Technical — Project Brief

## 1. Project Overview

**Project name:** Aris Technical

**Purpose:**  
Aris Technical is a technical knowledge and professional services website focused specifically on the technical side of ARIS.

The website has two primary goals:

1. **Technical knowledge resource**  
   Publish useful, practical ARIS technical articles, tutorials, solutions, examples, and troubleshooting guides.

2. **Professional lead generation**  
   Establish the author as an ARIS technical expert and generate:
   - Freelance/consulting opportunities
   - ARIS implementation/integration projects
   - Technical support opportunities
   - Job opportunities
   - Professional contacts

ARIS technical expertise is a relatively niche field. The website should take advantage of this by building strong topical authority around technical ARIS searches.

The site should **not feel like a generic consulting company website with a blog attached**.

Technical content should be the core of the website. Consulting/services should naturally be presented alongside that expertise.

---

# 2. Core SEO Objective

SEO is a **primary requirement**, not an afterthought.

The long-term goal is for Aris Technical to appear prominently when users search Google for ARIS technical topics.

Examples of desirable searches include:

- ARIS technical
- ARIS technical consultant
- ARIS developer
- ARIS consultant
- ARIS technical support
- ARIS administration
- ARIS scripting
- ARIS report script
- ARIS Process Governance
- ARIS APG
- ARIS automation
- ARIS REST API
- ARIS Repository API
- ARIS integration
- ARIS API integration
- ARIS LDAP
- ARIS SSO
- ARIS installation
- ARIS setup
- ARIS troubleshooting

The strategy should especially target **long-tail technical searches**.

For example:

- How to authenticate with ARIS REST API
- ARIS REST API 401 Unauthorized
- How to synchronize LDAP users with ARIS
- ARIS report script examples
- How to integrate ARIS with Power BI
- How to retrieve ARIS models using REST API
- How to install ARIS Server

These searches may have relatively low search volume, but visitors performing them are highly relevant.

A visitor may be an:

- ARIS administrator
- ARIS developer
- Enterprise architect
- Solution architect
- IT manager
- Consultant
- Employee of a company using ARIS

Therefore, **quality and relevance of traffic are more important than raw visitor numbers.**

# 8. Articles

Articles are expected to become the **main SEO engine of the website**.

The main Articles page should display the five categories:

1. ARIS Administration
2. ARIS Scripting
3. ARIS Process Governance (APG) & Automation
4. ARIS REST API & Integrations
5. ARIS Installation & Setup

Each category should have its own dedicated landing page.

Suggested URL structure:

```text
/articles/

/articles/administration/
/articles/scripting/
/articles/apg-automation/
/articles/rest-api-integrations/
/articles/installation-setup/
```

Individual articles should exist underneath their relevant category.

Example:

```text
/articles/rest-api-integrations/repository-api-authentication/

/articles/administration/ldap-user-synchronization/

/articles/scripting/export-model-data-to-excel/
```

Exact URL naming can be improved if there is an SEO or architectural reason, but URLs should remain:

- Short
- Descriptive
- Human-readable
- Stable

---

# 9. Article Category Pages

Category pages should NOT simply be filtered lists of articles.

Each category page should be a useful SEO landing page containing:

- H1
- Introductory description
- Relevant technical terminology
- List/grid of articles
- Internal links
- Potential link to relevant consulting services

For example:

# ARIS REST API & Integrations

Technical guides for working with ARIS REST APIs and integrating ARIS with external applications. Learn about authentication, repository access, data exchange, automation and enterprise system integrations.

[Article list follows]

This allows Google to understand the site's content hierarchy:

```text
Aris Technical
    ↓
ARIS REST API & Integrations
    ↓
Individual API tutorials
```

# 10. Individual Article Pages

Articles should be optimized both for **human readability and search engines**.

Every article should support:

- Article title
- SEO title
- Meta description
- URL slug
- Category
- Publication date
- Last updated date
- Author
- Article content
- Headings (H2/H3/etc.)
- Code blocks
- Images/screenshots
- Image alt text
- Links
- Internal links to related articles
- Tags where useful
- Related articles
- CTA to relevant services

Technical articles will often contain:

- JavaScript
- JSON
- XML
- REST requests/responses
- HTTP examples
- Configuration files
- Command-line commands
- Logs
- Error messages

Code presentation should therefore be a first-class part of the article design.

- ARIS report scripting examples

- APG workflow development
- Integrating ARIS with CMDB systems
- Integrating ARIS with Power BI
- ARIS installation/configuration
- Common ARIS administration problems

Article topics should be chosen based on a combination of:

**real ARIS technical usefulness + likely Google search intent.**

# 14. Future Administration System

The website will eventually need a private administration interface.

This does NOT necessarily need to be implemented in the first version, but the architecture should not make adding it unnecessarily difficult.

Potential route:

```text
/admin
```

The purpose is to allow the site owner to manage articles without editing source code.

Expected functionality eventually includes:

## Article Management

```text
Articles

+ New Article

Title                         Category               Status
----------------------------------------------------------------
LDAP synchronization          Administration         Published
Repository API auth           REST API               Published
APG approval workflow         APG                    Draft
```

The administrator should eventually be able to:

- Create articles
- Edit articles
- Delete articles
- Save drafts
- Publish/unpublish articles
- Select categories
- Configure URL slugs
- Add images
- Add code blocks
- Set publication dates
- Set SEO metadata
- Preview articles

A CMS, headless CMS or custom administration interface can be evaluated later.

Do not over-engineer V1 solely for this requirement.

Example:

An article about:

- ARIS Repository API Guide

- Professional
- Modern
- Clean
- Minimal
- Trustworthy

- A generic corporate consultancy
- A marketing-heavy SaaS landing page

# 20. Important Product Principle

The central idea behind Aris Technical is:

> **Demonstrate expertise by being genuinely useful.**

The website should primarily help people solve real ARIS technical problems.

Consulting and professional opportunities should emerge from the credibility created by that technical content.

SEO should therefore focus on creating the best possible answers to niche ARIS technical searches rather than creating generic keyword-heavy pages.
